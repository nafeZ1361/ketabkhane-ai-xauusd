# 03 — AGENT PROTOCOL (how to work here without breaking the project)

## 1. Session loop

```
read state  →  narrow the question  →  smallest change  →  focused tests
            →  full suite  →  evidence  →  decision record (if a contract changed)
            →  independent review  →  report
```

Never skip straight to code. The first useful thing you produce is a precise statement of what is
already true — the second is the smallest diff that changes it.

## 2. Git discipline

- Work on `fix/w1-timezone-validation` unless a human names another branch.
- **Never** run `commit`, `push`, `pull`, `fetch`, `merge`, `rebase`, `reset`, `amend`, `stash`,
  `clean`, `checkout -- .`, or delete a branch without an explicit request for that exact action.
- **Never** `git add -A`. The S5 evidence file is intentionally untracked; add explicit paths only.
- Before and after any work, record `git rev-parse HEAD` and `git status --porcelain`. If the
  before/after differ and you did not intend it, you have a finding, not a clean session.
- The S5 commit `9a3b53a` must never be recreated, amended or replaced. It is the accepted baseline.
- `origin/fix/w1-timezone-validation` is behind local (`08ce5f3`). That is expected; do not
  "repair" it by pushing.

## 3. Change discipline

- Smallest edit that satisfies the written requirement. No drive-by refactors, no formatting
  sweeps, no dependency upgrades, no "while I was here" fixes.
- If you find a defect in an **already accepted** stage: do not silently fix it. Write it up as a
  numbered residual (R-item) with location, impact and a fix direction, and let a human decide.
- New file > edited applied migration. New evidence file > edited evidence file.
- Comments and docstrings must not claim more than the code checks. Overclaiming was a real
  finding on this project (R2 in `01_STATE_SNAPSHOT.md`).

## 4. Testing

```powershell
# from ایجنت/xauusd-guardian/
C:\Python311\python.exe -m pytest tests/unit/<file> -v      # while iterating
C:\Python311\python.exe -m pytest -q                        # before claiming anything
C:\Python311\python.exe -m compileall -q src scripts tests
```

- A test that only greps source text is not a behavioural test. Exercise the behaviour.
- Prefer a **mutation probe**: remove the protection, watch the test go red, restore. A test that
  survives its own mutation is decoration.
- Never mark `xfail`/`skip` to get green. Never relax an assertion to match a bug.
- Record exact commands, exit codes and counts. "Should pass" is not evidence (AGENTS.md).
- Full suite is ~45 s and 267 tests; use targeted runs while iterating, one full run at the end.

## 5. Evidence format

`evidence/<phase>-<STAGE>-<UTCstamp>.txt` plus `<same>.sha256`, generated by a script that runs the
commands. Minimum content:

```
GENERATED_UTC, PYTHON, PYTEST
BRANCH, HEAD, HEAD_SUBJECT, HEAD_PARENT, S5_IS_HEAD, MAIN, PARALLEL
CHANGED FILES (git status --porcelain) + git diff --stat
SHA-256 OF CHANGED FILES   (raw bytes; say so)
TARGETED TESTS  (command, exit code, node count)
FULL SUITE      (command, exit code, junit tests/failures/errors/skipped)
COMPILEALL      (exit code)
MUTATION PROBES (each mutation, which test died, summary line)
DEMO / LIFECYCLE OUTPUT (verbatim)
SUMMARY         (one line, machine-readable)
```

Rules: values are copied from real output; unsigned hashes are meaningless; the `.sha256` sidecar is
written after the body, so the body cannot list its own digest.

If you must cite a reversal, cite the `down_sha256` that `reversal_plan` returns — not a container
digest, not a screenshot.

## 6. Reporting

Write to a file, not only to chat. Structure:

1. verdict (`PASS` / `BLOCK` / `PARTIAL`) and one-paragraph why;
2. exact changed paths, each mapped to the requirement it satisfies;
3. commands, exit codes, counts;
4. evidence file names and digests;
5. residuals with location + impact + fix direction;
6. what you did **not** do (scope explicitly), and what you could not verify;
7. the next gate and its entry condition.

Be explicit about limits: unpushed commits, missing refs in a clone, no live database. The Inspector
on this project earned trust by stating what it did *not* cover.

## 7. Token discipline (the reason this pack exists)

- Read `01_STATE_SNAPSHOT.md`, then only the files your task touches. Use `rg`/`grep`, not full reads.
- Don't paste whole test output into your context: `pytest -q` tail + junit counts is enough.
- Don't restate the repository in prose. Cite `path:line`.
- Prefer a 20-line probe script over reading five modules.
- When a decision is already recorded in `DECISIONS_LOG.md`, cite the D-number instead of re-deriving.
- If a question needs more than three files to answer, it is probably two questions.

## 8. Stop conditions (stop and report, do not improvise)

- the requirement is ambiguous, or two documents disagree;
- the change would need a new dependency, a new migration framework, or an edited applied migration;
- the change would touch Phase 4+ scope without authorization;
- a test fails for a reason you cannot explain;
- you would have to commit, push, fetch or rewrite history to proceed;
- you would have to connect to MT5 or touch an order path — **never**, at any stage.

## 9. Definition of done (single line)

Requirement satisfied + focused test that dies without the fix + full suite green with recorded exit
codes + evidence file with digests + residuals declared + independent `PASS`.
