### [1] DESIGN
New additive table schema_object_identity(version, kind, name, schema_rowid, rootpage,
sql_sha256, schema_version). The token is measured at apply, inside the same transaction as
the DDL and the ledger row, and verified in reversal_plan BEFORE any DROP. Identity is decided
by (schema_rowid, rootpage, sql_sha256); schema_version is recorded for diagnostics only,
because it is global and changes on any DDL (including CREATE TEMP TABLE) - using it as a
refusal signal blocked legitimate reverts during development and was removed.
Legacy databases (applied before the token) refuse to revert.

### [2] MEASURED SQLITE BEHAVIOUR (design probe)
DROP TABLE + CREATE TABLE with a byte-identical definition REUSES sqlite_master.rowid and
rootpage (observed 1->1, 2->2). VACUUM did not change them in that probe. This is why the
token is a triple and why the byte-identical, index-free case remains a documented limitation.
