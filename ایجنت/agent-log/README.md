# Agent Log — قاعدهٔ ثبت اجباری

**قاعده (۱۴۰۵/۰۹/۰۱ ≈ 2026-11-21):** هر کار و هر بازرسی — چه PASS، چه BLOCK، چه
`INDEPENDENCE_NOT_ESTABLISHED` — باید به‌صورت یک فایل Markdown ثبت شود و **در دو محل** نگه داشته شود:

1. `docs/agent-log/` در ریشهٔ مخزن
2. `ایجنت/agent-log/` در پوشهٔ پروژهٔ ایجنت

هر دو نسخه باید یکسان باشند (نسخهٔ اصلی همین‌جاست؛ نسخهٔ `ایجنت/agent-log/` آینهٔ بایت‌به‌بایت است).

## چه چیزی باید ثبت شود

| مورد | الزام |
|---|---|
| شناسهٔ کار | تاریخ + عنوان کوتاه |
| نقش انجام‌دهنده | Developer / Inspector / Orchestrator + نام دقیق ایجنت یا حساب |
| ورودی و دامنه | چه فایل‌ها/کامیت‌هایی، چه چیزی خارج از دامنه بود |
| تغییرات | فایل‌های تغییریافته + SHA-256 |
| تست‌ها | فرمان، exit code، تعداد pass/fail |
| حکم | `PASS` / `BLOCK` / `INDEPENDENCE_NOT_ESTABLISHED` / `NOT_RUN` |
| شواهد | مسیر فایل شاهد + SHA-256 |
| باقی‌مانده | بلاکرها، تصمیم‌های مالک |

## قاعده‌های سخت

- حکم بدون شاهد ثبت نمی‌شود؛ «باید پاس شود» شاهد نیست.
- بازرسی‌ای که انجام نشده، `NOT_RUN` ثبت می‌شود، نه PASS.
- خودتأییدی ممنوع: اگر بازرس مستقل نبود، `INDEPENDENCE_NOT_ESTABLISHED` ثبت می‌شود.
- شواهد قبلی بازنویسی نمی‌شوند؛ اصلاح با رکورد جدید و ارجاع به قبلی.
- هر ورودی جدید در **هر دو** پوشه اضافه می‌شود؛ فایل قدیمی دست‌نخورده می‌ماند.

## الگوی فایل جدید

```markdown
# <YYYY-MM-DD> — <عنوان کار>

- ROLE: <Developer|Inspector|Orchestrator> · ACTOR: <agent/account>
- SCOPE: <چه چیزی مجاز بود، چه چیزی خارج بود>
- BASE: HEAD <sha> · worktree <n M / n ??> · snapshot <sha256>
- CHANGED: <path> — <sha256>
- TESTS: `<cmd>` → exit <n>, <passed>/<failed>
- VERDICT: <PASS|BLOCK|INDEPENDENCE_NOT_ESTABLISHED|NOT_RUN>
- EVIDENCE: <path> — <sha256>
- REMAINING: <بلاکرها / تصمیم مالک>
```
